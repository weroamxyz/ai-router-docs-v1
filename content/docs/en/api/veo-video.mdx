Google Veo provides text-to-video, image-to-video, first-and-last-frame, and reference-image generation through the same asynchronous video API.

---

## Supported Models

| Model | Description |
| --- | --- |
| **veo-3.1-generate-preview** | Veo 3.1 video generation model; supports every mode documented below |
| **veo-3.1-fast-generate-preview** | Faster Veo 3.1 generation model; reference images are not supported |

---

## Overview

All generation modes use `POST /v1/video/generations`. The request fields determine the mode: omit image fields for text-to-video, provide `image` for image-to-video, add `metadata.lastFrame` to control the final frame, or provide `metadata.referenceImages` for asset and style references.

Generation is asynchronous:

1. Submit a generation task.
2. Poll its status using the returned task ID.
3. Retrieve the generated video from the returned URL or base64 data.

### Task Status Flow

```
queued → processing → succeeded
                 ↓
               failed
```

> Depending on the provider, a completed video is returned as base64 data in `bytes_base64_encoded` or through the URL in `url`.

## 1. Submit Video Generation Task (/v1/video/generations)

Choose the tab that matches your input and adjust the shared optional metadata as needed.

### Usage Examples

<ExampleTabs
  items={[
    'Text-to-video',
    'Image-to-video',
    'First/last frames',
    'Reference images',
  ]}
>
  <ExampleTab id="text-to-video-example">
    Omit all image fields to generate a video from text alone.

    ```json
    {
      "model": "veo-3.1-generate-preview",
      "prompt": "A cat playing piano in a beautiful garden",
      "metadata": {
        "aspectRatio": "16:9",
        "durationSeconds": 8,
        "negativePrompt": "blurry, low quality",
        "personGeneration": "allow_all",
        "resolution": "1080p",
        "sampleCount": 1
      }
    }
    ```
  </ExampleTab>

  <ExampleTab id="image-to-video-example">
    Provide a base64-encoded image in `image`. It becomes the video's first frame.

    ```json
    {
      "model": "veo-3.1-generate-preview",
      "prompt": "The cat begins playing the piano as flowers sway in the breeze",
      "image": "<BASE64_ENCODED_IMAGE_DATA>",
      "metadata": {
        "aspectRatio": "16:9",
        "durationSeconds": 8,
        "personGeneration": "allow_adult"
      }
    }
    ```
  </ExampleTab>

  <ExampleTab id="first-last-frame-example">
    Use `image` for the first frame and `metadata.lastFrame` for the last frame. This mode is supported by Veo 3.1 models.

    ```json
    {
      "model": "veo-3.1-generate-preview",
      "prompt": "The garden changes gradually from sunrise to sunset",
      "image": "<BASE64_ENCODED_FIRST_FRAME>",
      "metadata": {
        "lastFrame": "<BASE64_ENCODED_LAST_FRAME>",
        "durationSeconds": 8
      }
    }
    ```
  </ExampleTab>

  <ExampleTab id="reference-images-example">
    Provide the first-frame `image` plus up to three asset or style references in
    `metadata.referenceImages`. This mode is only supported by
    `veo-3.1-generate-preview`.

    ```json
    {
      "model": "veo-3.1-generate-preview",
      "prompt": "A cat plays piano in a garden matching the supplied visual style",
      "image": "<BASE64_ENCODED_FIRST_FRAME>",
      "metadata": {
        "referenceImages": [
          {
            "image": "<BASE64_ENCODED_CAT_REFERENCE>",
            "referenceType": "asset"
          },
          {
            "image": "<BASE64_ENCODED_STYLE_REFERENCE>",
            "referenceType": "style"
          }
        ]
      }
    }
    ```
  </ExampleTab>
</ExampleTabs>

### Complete Request

```bash
curl -X POST "((SITE_URL))/v1/video/generations" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer API_KEY" \
  -d @request-body.json
```

### Request Headers

| Header | Required | Value |
| --- | --- | --- |
| `Content-Type` | Yes | `application/json` |
| `Authorization` | Yes | `Bearer API_KEY` |

### Request Body Fields

<ParameterTree>
  <ParameterField id="veo-request-model" name="model" type="string" required>
    Veo model name. Use `veo-3.1-generate-preview` or
    `veo-3.1-fast-generate-preview`.
  </ParameterField>
  <ParameterField id="veo-request-prompt" name="prompt" type="string" required>
    Text prompt describing the video to generate.
  </ParameterField>
  <ParameterField id="veo-request-image" name="image" type="string">
    Base64-encoded first-frame image. Required for image-to-video and
    first-and-last-frame and reference-image generation; omit for text-to-video.
  </ParameterField>
  <ParameterField id="veo-request-metadata" name="metadata" type="object">
    Optional generation settings and additional image inputs.
    <ParameterChildren>
      <ParameterField id="veo-request-metadata-aspect-ratio" name="aspectRatio" type="string">
        Output aspect ratio. Accepts `16:9` or `9:16`.
      </ParameterField>
      <ParameterField id="veo-request-metadata-duration" name="durationSeconds" type="number">
        Video duration in seconds. Accepts `4`, `6`, or `8`.
      </ParameterField>
      <ParameterField id="veo-request-metadata-negative-prompt" name="negativePrompt" type="string">
        Content or visual qualities to exclude from the generated video.
      </ParameterField>
      <ParameterField id="veo-request-metadata-person-generation" name="personGeneration" type="string">
        Person-generation policy. Use `allow_all` for text-to-video or
        `allow_adult` for image-to-video where supported.
      </ParameterField>
      <ParameterField id="veo-request-metadata-resolution" name="resolution" type="string">
        Output resolution, such as `720p` or `1080p`.
      </ParameterField>
      <ParameterField id="veo-request-metadata-sample-count" name="sampleCount" type="number">
        Number of videos to generate. Defaults to `1`.
      </ParameterField>
      <ParameterField id="veo-request-metadata-storage-uri" name="storageUri" type="string">
        Google Cloud Storage URI where generated videos should be stored.
      </ParameterField>
      <ParameterField id="veo-request-metadata-last-frame" name="lastFrame" type="string">
        Base64-encoded last-frame image for first-and-last-frame generation.
      </ParameterField>
      <ParameterField id="veo-request-metadata-reference-images" name="referenceImages" type="object[]">
        Up to three asset or style references. Supported only by
        `veo-3.1-generate-preview`.
        <ParameterChildren>
          <ParameterField id="veo-request-reference-image" name="image" type="string" required>
            Base64-encoded reference image.
          </ParameterField>
          <ParameterField id="veo-request-reference-type" name="referenceType" type="string" required>
            Reference role. Accepts `asset` or `style`.
          </ParameterField>
        </ParameterChildren>
      </ParameterField>
    </ParameterChildren>
  </ParameterField>
</ParameterTree>

### Response Example

```json
{
  "id": "TASK_ID",
  "task_id": "TASK_ID",
  "object": "video",
  "model": "veo-3.1-generate-preview",
  "status": "queued",
  "progress": 0,
  "created_at": 1764616538
}
```

### Response Body Fields

<ParameterTree requiredLabel="Always" optionalLabel="Conditional">
  <ParameterField id="veo-submit-id" name="id" type="string" required>
    Task ID for subsequent status queries.
  </ParameterField>
  <ParameterField id="veo-submit-task-id" name="task_id" type="string">
    Alias of `id`; included by some response paths.
  </ParameterField>
  <ParameterField id="veo-submit-object" name="object" type="string" required>
    Object type. Always `video`.
  </ParameterField>
  <ParameterField id="veo-submit-model" name="model" type="string" required>
    Model used for generation.
  </ParameterField>
  <ParameterField id="veo-submit-status" name="status" type="string" required>
    Initial task status, normally `queued`.
  </ParameterField>
  <ParameterField id="veo-submit-progress" name="progress" type="integer" required>
    Initial progress value, normally `0`.
  </ParameterField>
  <ParameterField id="veo-submit-created" name="created_at" type="integer" required>
    Unix task-creation timestamp.
  </ParameterField>
</ParameterTree>

## 2. Query Task Status (/v1/video/generations/\{task_id\})

### Complete Request

```bash
curl -X GET "((SITE_URL))/v1/video/generations/TASK_ID" \
  -H "Authorization: Bearer API_KEY"
```

### Request Headers

| Header | Required | Value |
| --- | --- | --- |
| `Authorization` | Yes | `Bearer API_KEY` |

### Path Parameters

<ParameterTree>
  <ParameterField id="veo-video-table-task-id-1" name="task_id" type="string" required>

    Task ID returned when generation was submitted
  </ParameterField>
</ParameterTree>

### Response Examples

<ExampleTabs items={['Processing', 'Success', 'Failed']}>
  <ExampleTab id="veo-processing-response">
    ```json
    {
      "code": "success",
      "message": "",
      "data": {
        "bytes_base64_encoded": "",
        "error": null,
        "format": "mp4",
        "metadata": null,
        "status": "processing",
        "task_id": "TASK_ID",
        "url": ""
      }
    }
    ```
  </ExampleTab>
  <ExampleTab id="veo-success-response">
    ```json
    {
      "code": "success",
      "message": "",
      "data": {
        "bytes_base64_encoded": "",
        "error": null,
        "format": "mp4",
        "metadata": null,
        "status": "succeeded",
        "task_id": "TASK_ID",
        "url": "((SITE_URL))/v1/videos/TASK_ID/content"
      }
    }
    ```
  </ExampleTab>
  <ExampleTab id="veo-failed-response">
    ```json
    {
      "code": "success",
      "message": "",
      "data": {
        "bytes_base64_encoded": "",
        "error": null,
        "format": "mp4",
        "metadata": null,
        "status": "failed",
        "task_id": "TASK_ID",
        "url": "Reference to video does not support this mix of reference images."
      }
    }
    ```

    When a task fails, `url` may contain the provider error message instead of a
    video URL.
  </ExampleTab>
</ExampleTabs>

### Response Body Fields

<ParameterTree requiredLabel="Always" optionalLabel="Conditional">
  <ParameterField id="veo-status-code" name="code" type="string" required>
    Wrapper status. `success` means the query itself completed successfully.
  </ParameterField>
  <ParameterField id="veo-status-message" name="message" type="string" required>
    Wrapper message, usually empty for a successful query.
  </ParameterField>
  <ParameterField id="veo-status-data" name="data" type="object" required>
    Task state and generated output.
    <ParameterChildren>
      <ParameterField id="veo-status-task-id" name="task_id" type="string" required>
        Generation task ID.
      </ParameterField>
      <ParameterField id="veo-status-state" name="status" type="string" required>
        Task status, such as `queued`, `processing`, `succeeded`, or `failed`.
      </ParameterField>
      <ParameterField id="veo-status-format" name="format" type="string" required>
        Video format, normally `mp4`.
      </ParameterField>
      <ParameterField id="veo-status-url" name="url" type="string">
        Video access URL on success. On some failures, this contains the provider
        error message.
      </ParameterField>
      <ParameterField id="veo-status-base64" name="bytes_base64_encoded" type="string">
        Base64-encoded video returned by providers such as Vertex.
      </ParameterField>
      <ParameterField id="veo-status-error" name="error" type="object | null">
        Error details when the provider returns a structured error.
      </ParameterField>
      <ParameterField id="veo-status-metadata" name="metadata" type="object | null">
        Provider metadata, including Responsible AI filtering information when
        applicable.
        <ParameterChildren>
          <ParameterField id="veo-status-filtered-count" name="rai_media_filtered_count" type="integer">
            Number of outputs blocked by Responsible AI filtering.
          </ParameterField>
          <ParameterField id="veo-status-filtered-reasons" name="rai_media_filtered_reasons" type="string[]">
            Provider explanations for filtered outputs.
          </ParameterField>
        </ParameterChildren>
      </ParameterField>
    </ParameterChildren>
  </ParameterField>
</ParameterTree>

## Important Notice

Due to [Google's Responsible AI Guidelines](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/responsible-ai-and-usage-guidelines), Gemini-channel tasks can finish successfully while their outputs are blocked. Check `data.metadata.rai_media_filtered_count` and `data.metadata.rai_media_filtered_reasons` before treating an empty result as a transport failure.
