xAI's Grok Imagine provides video generation models. This document describes the API interface for using Grok video models for video generation. All video generation calls use the same `/v1/video/generations` endpoint, with different parameters depending on the use case.

---

## Supported Models

Currently supported models include:

| Model | Description |
| --- | --- |
| **grok-imagine-video** | Grok Imagine video generation model (text-to-video, image-to-video, reference-to-video) |

---

## Overview

The Grok video generation feature provides an asynchronous task processing mechanism:

1. Submit Task: Send a text prompt (and optionally one or more images) to create a video task
2. Query Status: Query generation progress and status through task ID
3. Get Results: Retrieve the generated video file after task completion

The same `/v1/video/generations` endpoint serves three use cases, selected by whether `images` is present and by `metadata.imageMode`: no `images` performs text-to-video; `images` with `metadata.imageMode` omitted or set to `"keyframe"` (the default) performs image-to-video, using only the first image; `images` with `metadata.imageMode` set to `"reference"` performs reference-to-video.

### Task Status Flow

```
queued → in_progress → completed
                ↓
            failed
```

- queued: Task has been submitted and is waiting to be processed
- in_progress: Task is being processed
- completed: Task completed successfully, video has been generated
- failed: Task failed

> **Note:** Grok video does not support push callbacks. Poll [2. Query Task Status](#2-query-task-status-v1videogenerationstask_id) until the task reaches a terminal status.

## 1. Submit Video Generation Task (/v1/video/generations)

Choose the example that matches how you want to generate the video, then adjust its request body for your scenario.

### Usage Examples

<ExampleTabs
  items={['Text-to-video', 'Image-to-video', 'Reference-to-video']}
>
  <ExampleTab id="text-to-video-example">
    Text-to-video uses `prompt` and `model` only—no `images`. Optional
    top-level fields include `duration` and `size`. `aspect_ratio` is set via
    `metadata`.

    **Request body:**

    ```json
    {
      "prompt": "A glowing crystal-powered rocket launching from the red dunes of Mars",
      "model": "grok-imagine-video",
      "duration": 10,
      "size": "720p",
      "metadata": {
        "aspect_ratio": "16:9"
      }
    }
    ```

    **Request parameters:**

    <ParameterTree>
      <ParameterField id="text-prompt" name="prompt" type="string" required>
        Text prompt for the video.
      </ParameterField>
      <ParameterField id="text-model" name="model" type="string" required>
        Model name. Use `grok-imagine-video`.
      </ParameterField>
      <ParameterField id="text-duration" name="duration" type="integer" required>
        Video duration in seconds. Accepts integers from `1` to `15`, inclusive.
      </ParameterField>
      <ParameterField id="text-size" name="size" type="string">
        Output resolution. Defaults to `480p`; accepts `480p`, `720p`, or
        `1080p`.
      </ParameterField>
      <ParameterField id="text-metadata" name="metadata" type="object">
        Extra metadata for the generation request.
        <ParameterChildren>
          <ParameterField
            id="text-metadata-aspect-ratio"
            name="aspect_ratio"
            type="string"
          >
            Video aspect ratio. xAI applies `16:9` when omitted. Accepts `1:1`,
            `16:9`, `9:16`, `4:3`, `3:4`, `3:2`, or `2:3`.
          </ParameterField>
        </ParameterChildren>
      </ParameterField>
    </ParameterTree>
  </ExampleTab>

  <ExampleTab id="image-to-video-example">
    Provide one or more image URLs (or base64 data URIs) in `images` with
    `metadata.imageMode` omitted or set to `"keyframe"` (the default). Only the
    **first** image in the array is used—it becomes the video's locked first
    frame; any additional images are ignored.

    **Request body:**

    ```json
    {
      "prompt": "The rocket's engines ignite and it lifts off in a cloud of dust",
      "model": "grok-imagine-video",
      "images": ["https://example.com/rocket-on-launchpad.jpg"],
      "duration": 8,
      "size": "720p",
      "metadata": {
        "aspect_ratio": "16:9"
      }
    }
    ```

    **Request parameters:**

    <ParameterTree>
      <ParameterField id="image-prompt" name="prompt" type="string" required>
        Text prompt describing how the image should animate.
      </ParameterField>
      <ParameterField id="image-model" name="model" type="string" required>
        Model name. Use `grok-imagine-video`.
      </ParameterField>
      <ParameterField id="image-images" name="images" type="string[]" required>
        One or more image URLs or base64 data URIs. Only the **first** image is
        used, becoming the locked first frame.
      </ParameterField>
      <ParameterField id="image-duration" name="duration" type="integer" required>
        Video duration in seconds. Accepts integers from `1` to `15`, inclusive.
      </ParameterField>
      <ParameterField id="image-size" name="size" type="string">
        Output resolution. Defaults to `480p`; accepts `480p`, `720p`, or
        `1080p`.
      </ParameterField>
      <ParameterField id="image-metadata" name="metadata" type="object">
        Extra metadata for the generation request.
        <ParameterChildren>
          <ParameterField
            id="image-metadata-image-mode"
            name="imageMode"
            type="string"
          >
            Image handling mode. Defaults to `keyframe`; use `keyframe` or omit
            this field for image-to-video.
          </ParameterField>
          <ParameterField
            id="image-metadata-aspect-ratio"
            name="aspect_ratio"
            type="string"
          >
            Video aspect ratio. Defaults to `16:9`; accepts `1:1`, `16:9`,
            `9:16`, `4:3`, `3:4`, `3:2`, or `2:3`.
          </ParameterField>
        </ParameterChildren>
      </ParameterField>
    </ParameterTree>

    > **Note:** Image-to-video does not support a separate last-frame image. To
    > use multiple images without locking a frame, choose the
    > **Reference-to-video** tab.
  </ExampleTab>

  <ExampleTab id="reference-to-video-example">
    Set `metadata.imageMode` to `"reference"` so every URL in `images` is treated
    as a **reference image** that influences the video without locking any
    frame. Reference images by position in the prompt with tags such as
    `<IMAGE_1>`, `<IMAGE_2>`, … in the same order as `images`.

    **Request body:**

    ```json
    {
      "prompt": "The model from <IMAGE_1> walks the runway wearing the shirt from <IMAGE_2>",
      "model": "grok-imagine-video",
      "images": [
        "https://example.com/model-reference.jpg",
        "https://example.com/shirt-reference.jpg"
      ],
      "duration": 10,
      "size": "720p",
      "metadata": {
        "imageMode": "reference",
        "aspect_ratio": "16:9"
      }
    }
    ```

    **Request parameters:**

    <ParameterTree>
      <ParameterField id="reference-prompt" name="prompt" type="string" required>
        Text prompt. Use `<IMAGE_1>` through `<IMAGE_N>` to refer to images in
        array order.
      </ParameterField>
      <ParameterField id="reference-model" name="model" type="string" required>
        Model name. Use `grok-imagine-video`.
      </ParameterField>
      <ParameterField
        id="reference-images"
        name="images"
        type="string[]"
        required
      >
        One or more reference image URLs or base64 data URIs.
      </ParameterField>
      <ParameterField
        id="reference-duration"
        name="duration"
        type="integer"
        required
      >
        Video duration in seconds. Accepts integers from `1` to `15`, inclusive.
      </ParameterField>
      <ParameterField id="reference-size" name="size" type="string">
        Output resolution. Defaults to `480p`; accepts `480p`, `720p`, or
        `1080p`.
      </ParameterField>
      <ParameterField id="reference-metadata" name="metadata" type="object">
        Metadata for reference-image handling. `imageMode` is required for this
        mode.
        <ParameterChildren>
          <ParameterField
            id="reference-metadata-image-mode"
            name="imageMode"
            type="string"
            required
          >
            Set to `reference`.
          </ParameterField>
          <ParameterField
            id="reference-metadata-aspect-ratio"
            name="aspect_ratio"
            type="string"
          >
            Video aspect ratio. Defaults to `16:9`; accepts `1:1`, `16:9`,
            `9:16`, `4:3`, `3:4`, `3:2`, or `2:3`.
          </ParameterField>
        </ParameterChildren>
      </ParameterField>
    </ParameterTree>
  </ExampleTab>
</ExampleTabs>

### Complete Request:

```bash
curl -X POST "((SITE_URL))/v1/video/generations" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer API_KEY" \
  -d @request-body.json
```

### Endpoint:

```
POST /v1/video/generations
```

### Request Headers:

<ParameterTree>
  <ParameterField id="grok-video-table-content-type-1" name="Content-Type" type="string" required>

    application/json
  </ParameterField>
  <ParameterField id="grok-video-table-authorization-2" name="Authorization" type="string" required>

    Bearer API_KEY
  </ParameterField>
</ParameterTree>

### Response Example:

```json
{
  "id": "TASK_ID",
```

## 2. Query Task Status (/v1/video/generations/\{task_id\})

### Complete Request:

```bash
curl -X GET "((SITE_URL))/v1/video/generations/TASK_ID" \
  -H "Authorization: Bearer API_KEY"
```

### Endpoint:

```
GET /v1/video/generations/{task_id}
```

### Request Headers:

<ParameterTree>
  <ParameterField id="grok-video-table-authorization-3" name="Authorization" type="string" required>

    Bearer API_KEY
  </ParameterField>
</ParameterTree>

### Path Parameters:

<ParameterTree>
  <ParameterField id="grok-video-table-task-id-4" name="task_id" type="string" required>

    Task ID
  </ParameterField>
</ParameterTree>

### Response Examples:

<ExampleTabs items={['Processing', 'Success']}>
  <ExampleTab id="processing-response-example">
    ```json
    {
      "code": "success",
      "message": "",
      "data": {
        "task_id": "<TASK_ID>",
        "action": "generate",
        "status": "IN_PROGRESS",
        "fail_reason": "",
        "submit_time": 1776717808,
        "start_time": 1776717809,
        "finish_time": 0,
        "progress": "50%",
        "data": {
          "status": "pending",
          "model": "grok-imagine-video"
        }
      }
    }
    ```
  </ExampleTab>

  <ExampleTab id="success-response-example">
    > **Note:** When the task succeeds, `data.fail_reason` contains the video

    > `data.data.video.url` when retrieving the generated video.

    ```json
    {
      "code": "success",
      "message": "",
      "data": {

        "finish_time": 1776717962,
        "progress": "100%",
        "data": {
          "status": "done",
          "model": "grok-imagine-video",
          "video": {
            "url": "<VIDEO_URL>",
            "duration": 8,
            "respect_moderation": true
          },
    ```
